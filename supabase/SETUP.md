# تشغيل الباك إند (Supabase) — خطوة بخطوة

1. أنشئ مشروع على supabase.com.
2. **SQL Editor** ← الصق `schema.sql` ← Run. ثم `seed.sql` ← Run.
3. **Authentication → Providers → Email:** أوقف **Confirm email** (لازم، لأن الدخول بالموبايل بيتحوّل لإيميل داخلي مش حقيقي).
4. **Authentication → Providers → Google:** فعّله وحط Client ID/Secret من Google Cloud Console.
   وفي **URL Configuration** أضف رابط موقعك النهائي (Site URL + Redirect URLs).
5. افتح `config.js` وحط `SUPABASE_URL` و`SUPABASE_ANON_KEY` (من Project Settings → API). **anon فقط، مش service_role.**
6. سجّل حساب على الموقع برقمك، وبعدين في SQL Editor:
   `update public.profiles set role='admin' where phone='01XXXXXXXXX';`
7. أرقام التحويل: هتعدّلها من لوحة الأدمن (أو مؤقتًا في جدول `payment_methods` → `account_details`).
8. ارفع الموقع على استضافة بـHTTPS (Vercel/Netlify) — Google Login مابيشتغلش من ملف محلي.

## الأمان في التصميم
- الطلب بيتحسب بالكامل داخل الدالة `create_order` على السيرفر (الأسعار، الخصم، الشحن، المخزون).
- الكوبونات مخفية عن العملاء (RLS)، والفحص عبر `validate_coupon` فقط، مع حد استخدام كلي ولكل عميل.
- العميل لا يرقّي نفسه أدمن (trigger `guard_role`)، ولا يشوف طلبات غيره.
- صور التحويل في bucket خاص: العميل يرفع في فولدره فقط، والأدمن يشوفها برابط مؤقت.
- رفع الصورة **لا** يؤكد الدفع؛ الأدمن فقط يحوّل `payment_status` إلى confirmed أو rejected.

## ملفات الموقع بعد التوصيل
| الملف | وظيفته |
|---|---|
| `config.js` | مفاتيح Supabase ورقم الواتساب (الملف الوحيد اللي بتعدّله) |
| `backend.js` | طبقة الاتصال بـSupabase |
| `auth.js` | نافذة التسجيل/الدخول (موبايل + كلمة سر / Google) |
| `shop.js` | الكتالوج والسلة من القاعدة (سعر حسب الوزن + المخزون) |
| `checkout.js` | الدفع: بيانات الشحن، طريقة الدفع، رفع الـScreenshot، صفحة النجاح |
| `account.html/js` | حساب العميل: بياناته، طلباته، حالة الدفع والطلب لحظيًا، الأكواد المستخدمة |
| `admin.html/js` | لوحة الأدمن: الطلبات وإثبات الدفع، المنتجات والمخزون، الكوبونات، الشحن، طرق الدفع، الحالات، الإعدادات |

> لو `config.js` فاضي، الموقع بيشتغل بالنظام القديم (بيانات ثابتة + طلب على واتساب).
> الأدمن: افتح `admin.html` بعد ما تعمل حسابك وتحوّله لأدمن (الخطوة 6).

## تحديث v8/v9: رسوم طرق الدفع
- لو قاعدتك شغالة بالفعل: شغّل `migration-v8.sql` مرة واحدة في SQL Editor. (للتركيب الجديد: `schema.sql` + `seed.sql` كفاية.)
- الرسوم بتتحدد لكل طريقة دفع من لوحة الأدمن ← طرق الدفع ← "رسوم إضافية". الافتراضي: الدفع عند الاستلام +20 ج. والسيرفر هو اللي يحسبها، العميل مايقدرش يعدّلها.

## تحديث v10
- قاعدة شغالة؟ شغّل `migration-v9.sql` (بعد v8): كوبونات 30 يوم بالكتير بيفرضها السيرفر، وصور إثبات الدفع للأدمن فقط.
- تبويب **محتوى الموقع** في لوحة الأدمن: الشريط العلوي، الواجهة، القصة، التواصل والسوشيال، الأسئلة، آراء العملاء، البوكسات، السياسات. الأسعار والمنتجات والمخزون من تبويب المنتجات.
- في وضع Supabase آراء العملاء والبوكسات بتظهر فقط لو الأدمن كتبها (مفيش آراء وهمية).
